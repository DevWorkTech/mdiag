# Протокол и проверенные границы

## Локальный API

Первый сегмент `/xdiag/` определяет профиль. Домен ограничен настройкой `http.domain`.
Авторизация через `passport_service.login` проверяет локальную БД; `data.token`, `data.user.user_id`
содержат только локальные значения. Пароли хешируются Laravel Hash. Токен хранится как SHA-256 для поиска
и в зашифрованном APP_KEY виде для проверки SOAP-подписи. После смены APP_KEY старые сессии отзывайте.

SOAP: `authenticate.cc` — ID локального пользователя; `sign=MD5(значения параметров по порядку + token)`.
JSON: `sign=MD5(отсортированные key=value через & + token)`; значения не URL-encoded,
как RequestParams.b() в APK. ID пользователя передаётся в user_id, token может отсутствовать.
Скачивание: заголовки `cc` и `sign=MD5(отсортированные по ключу значения параметров + token)`,
как DownloadManager/RequestParams.c(). Дополнительно принимаются Bearer и token локальных URL.
Запрос без валидного токена/подписи отклоняется. SN/ID пользователя сами по себе не дают доступа.

Реализованы:
- `config_service.urls`: только локальные URL;
- `passport_service.login/logout`, `userinfo.get_base_info`;
- локальная регистрация (по умолчанию отключена; новый пользователь заблокирован);
- `getRegisteredProductsForPad`: назначенные локальному пользователю сканеры;
- `queryLatestDiagSofts`, `queryLatestDiagSoftsBaseAllFunc`, `queryHistoryDiagSofts`, `queryLatestPublicSofts`;
- локальные загрузки через `mobile/softCenter/downloadDiagSoftWs.action`,
  `downloadEncryptDiagSoft.action`, `diagpointdown.php`.

Каталог возвращает только активные, физически существующие файлы разрешённых модулей.
Права пользователя и сканера пересекаются. Локальные versionDetailId являются ID записей БД.
Сохранённые URL поставщика, session/token поставщика и сырые SOAP-снимки планшету не выдаются.

Неизвестные операции, бинарные delta-пакеты, XMPP, регистрация/активация у поставщика,
генерация лицензий и экраны оплаты не эмулируются. Они завершаются локальной ошибкой.
Другие APK требуют собственного проверенного адаптера. Не заявляется совместимость со всеми экранами.

## Ошибки и уведомления

Из APK подтверждены `100001` (пароль), `100002` (нет пользователя), `40000` (домен),
`40001` (версия входа), `1023` (неполные параметры). Локальный вход использует общий 100001,
чтобы не раскрывать существование учётной записи. Собственные ограничения имеют коды 900001–900012;
их значения описаны в `Services/Local/ErrorCatalog.php`.

Таблица `mdiag_error_messages`: `provider`, `key`, `code`, `http_status`, `message`.
Пользовательские `denied_message`, `expired_message`, `module_denied_message` имеют приоритет над общим текстом.
`notification_text` возвращается при входе и запросе профиля. JSON/XML экранируются сериализаторами.
Штатные экраны APK могут показывать встроенный текст по коду, игнорируя message: для гарантированного
показа произвольного текста потребуется отдельная доработка интерфейса APK.

## Внешняя синхронизация

Обычный вход повторяет поля APK: `app_id=21035`, `ver=5.3.0`, `type=0`, `device`.
Пароль не хешируется в основной ветке; удаляются U+202C/U+202D, как в LoginActivity.

Резерв выполняется только после ошибки основного входа и при настроенном SN. Использует
`/diagdevice/app/user/login.php`, `username`, `serialNo`, `dateTime`, `MD5(MD5(password)+dateTime)`;
BaseManager APK дописывает отсортированные по ключам значения в путь. Для SOAP берётся
`data.deviceUser.cc/token`, а не `loginUser.token`. Учетная запись должна иметь права у поставщика.

SOAP 1.1 RPC/encoded отправляется на endpoint без `?wsdl`; Namespace `https://79.174.70.97`
является идентификатором XML и не означает обращение к этому IP. Используются 443 и резервный 8000.
Исправлено блокирование на GET WSDL. Это не доказывает доступность самого SOAP-сервиса.
Результат на реальном аккаунте проверяет владелец запуском `mdiag:sync xdiag --list`.

## Проверка 7.00.014

Исходный SHA-256: `609b6fdaaf059a36b5442fce28e1341794912a4dd8378a468b1833c4f0c9c423`.
Проверены BaseManager (`module.h.a`), RequestParams (`framework.network.http.g`),
DownloadManager (`framework.network.b.b`), login action (`module.b1.a.a`),
каталог (`module.upgrade.a.b`) и модель `module.upgrade.model.v`.
Методы queryLatestDiagSoftsIncrCdn/AllFunc получают **xdigPadSoftIncrList** и isCDNWork=0;
в нём полные локальные архивы. Инкрементальные бинарные патчи не генерируются.
Форматы подтверждены статическим анализом, end-to-end запуск на планшете ещё необходим.

Секреты, подписи и файлы лицензий поставщика не генерируются и не изменяются.
Резервный blockchain-вход предназначен для внешнего CLI-клиента. Локальные пользователи
используют штатный основной экран входа с обычным паролем; альтернативный экран локально не реализован.


## Динамические SOAP-адреса

Консольный клиент запрашивает `https://services.x-diag.info/?action=config_service.urls`
и читает `data.urls`. В разобранных классах APK проверка серверов вызывает загрузку
этой конфигурации; метод `getRegisteredProductsForPad` получает URL по ключу
`productservice.*` через менеджер адресов. Встроенный assets/configurl.json —
исходная таблица, она не гарантирует актуальность адресов.

Ответ официального сервера из диагностики содержит три адреса:
- `https://79.174.70.97/services/v2/productService.php?wsdl`;
- `https://79.174.70.97/services/v2/xdigPadDiagSoftService.php?wsdl`;
- `https://79.174.70.97/services/v2/xdigPadPublicSoftService.php?wsdl`.

IP добавлен в список доверенных хостов клиента. URL берётся целиком из ответа:
путь, порт и query не заменяются старым /services/. Ручная настройка
`sync.soap_endpoints` для этих адресов не нужна; она остаётся необязательным
приоритетным переопределением оператора. Тест воспроизводит конфигурационный
ответ и проверяет выбор всех трёх адресов. Он не подтверждает выполнение SOAP
с оплаченной сессией на внешнем сервере.
